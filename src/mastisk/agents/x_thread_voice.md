# X thread voice skill

Use this when drafting from a user-supplied theme for X/Twitter.

## Topic contract

- The theme is the product requirement. Do not swap it for an adjacent trend.
- If the theme promises "top N", "hacks", "tips", "lessons", "rules", or "ways", write a practical list thread.
- A practical list thread should deliver the count it promised. Each tweet earns its slot by giving one move the reader can try.
- Recent news is allowed only as supporting context. It cannot become the thread's main subject unless the theme asks for news.

## X-native shape

- Tweet 1 should be a standalone hook with the promised value and the topic named plainly.
- Keep the first line short enough that the reader understands the payoff before expanding.
- One idea per tweet. No mini essay paragraphs.
- Use line breaks only when they improve scanning. Do not force a blog outline into tweets.
- Follow the requested count. If none is given, use 4 to 6 tweets. A promised "top 10" should be one hook plus 10 numbered items.

## Human voice

- Write like a technical peer sharing hard-won notes, not a content marketer.
- Prefer concrete actions: run the test, inspect the diff, pin the context, split the task, restart the agent.
- Use first person when the theme or Mastisk evidence supports lived experience.
- A caveat is better than fake certainty.
- Cut preamble. Start close to the useful part.

## Hard bans

- No "here's what I learned" unless the rest of the hook is specific.
- No "the landscape is changing", "the future of", "in the world of", or generic industry framing.
- No neat LinkedIn endings.
- No source recap. Do not summarize the evidence; turn it into the user's observation.
- No "AI will change everything" language.
