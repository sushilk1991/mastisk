# Capture Subsystem — Phase 1: Ingress + Apple Watch Path — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a token-authed, internet-reachable capture ingress so a one-tap Apple Watch shortcut (Dictate Text → POST) lands a thought in Mastisk. In Phase 1 a capture **becomes a note** in the existing `_notes/inbox/` pipeline — the current Notetaker classifies it unchanged. **No intent routing, no new entity types yet** (those are Phase 2+). This proves the wrist→server loop end to end.

**Architecture:** A new `POST /api/capture` route (distinct from the localhost-trusted `/api/notes`) requires `Authorization: Bearer <token>`, then persists via a shared `persist_note_capture()` helper extracted from the existing `capture_note` handler. Reachability from the Watch uses **Cloudflare Tunnel** (the Watch is not a Tailscale client). Token lives in `config.toml` under `[capture]`, generated by a new `mastisk capture-token` CLI.

**Tech Stack:** Python 3.11+, FastAPI, sqlite3 (stdlib), pydantic-settings, typer, existing mastisk patterns. `cloudflared` (external, install step). Apple Shortcuts (manual authoring).

**Spec reference:** `docs/superpowers/specs/2026-06-09-tasks-journals-capture-design.md` — §3 (architecture), §7 (Watch path + security), §9 (API), §10 (config). Sister spine: `docs/superpowers/specs/2026-04-21-notes-subsystem-design.md`.

**Verified against current code (2026-06-09):** `derive_slug`/`atomic_write` live in `routes/notes.py:85,92`; `insert_note`/`get_note` in `db/queries.py:1373`; settings use a per-subsystem `BaseSettings` class merged from `config.toml` (`settings.py:177-236`); `update_toml_key()` (`settings.py:244`) does atomic single-key writes; routers register in `app.py:74-96` (notes router carries its own `/api/notes` prefix, added without the `/api` prefix arg).

@app.command(name="capture-token")
def capture_token(
    rotate: bool = typer.Option(False, "--rotate", help="Replace an existing token."),
) -> None:
    """Generate + store the bearer token for the /api/capture ingress.

    Prints the token once. Store it in your Apple Watch shortcut's
    Authorization header as `Bearer <token>`. Use --rotate to replace.
    """
    import secrets

    from mastisk.settings import get_settings, reload_settings, update_toml_key

    existing = get_settings().capture.bearer_token
    if existing and not rotate:
        typer.secho(
            "A capture token already exists. Re-run with --rotate to replace it "
            "(this invalidates the old token in your shortcut).",
            fg="yellow",
        )
        raise typer.Exit(code=1)

    token = secrets.token_urlsafe(32)
    update_toml_key("capture", "bearer_token", token)
    reload_settings()

    typer.secho("capture ingress token (store this — shown once):", fg="green")
    typer.echo(token)
    typer.echo("")
    typer.secho("In your Apple Watch shortcut, set the header:", fg="cyan")
    typer.echo(f"  Authorization: Bearer {token}")
    typer.echo("")
    typer.secho(
        "Reachability: the Watch is NOT a Tailscale client. Expose ONLY /api/capture "
        "via Cloudflare Tunnel (see README → 'Capturing from your Apple Watch').",
        fg="cyan",
    )
```

```python
def persist_note_capture(
    *,
    body: str,
    source: str,
    slug_text: str | None = None,
    ts: datetime | None = None,
) -> dict:
    """Write a captured note to the inbox and index it. Returns the DB row dict.

    Shared by POST /api/notes and POST /api/capture. Encapsulates the
    slug-collision file-reconcile dance so callers don't duplicate it.

    `slug_text` lets the filename reflect the user's own words even when
    `body` carries a prepended context preamble (the Open Questions flow);
    defaults to `body`.
    """
    ts = ts or datetime.now().astimezone()
    slug = derive_slug(slug_text if slug_text is not None else body, ts)
    target = notes_inbox_dir() / f"{slug}.md"
    atomic_write(target, body)
    rel_path = str(target.relative_to(vault_dir()))
    with connect() as conn:
        note_id = q.insert_note(
            conn, slug=slug, path=rel_path, body=body, source=source, created_at=ts,
        )
        row = q.get_note(conn, note_id)
    # On slug collision the DB path got a `-N` suffix; the file was written with
    # the original name — rename it to match what the DB recorded.
    actual_path = vault_dir() / row["path"]
    if actual_path != target:
        target.rename(actual_path)
    return dict(row)
```

```python
"""Capture ingress — the internet-exposed, token-authed front door.

Phase 1: a capture becomes a note in the existing _notes/inbox pipeline.
Intent routing (task/journal/project) arrives in Phase 2. See
docs/superpowers/specs/2026-06-09-tasks-journals-capture-design.md.
"""
from __future__ import annotations

import hmac
from typing import Literal

from fastapi import APIRouter, Header, HTTPException
from pydantic import BaseModel, Field, field_validator

from mastisk.routes.notes import persist_note_capture
from mastisk.settings import get_settings

router = APIRouter(prefix="/api/capture", tags=["capture"])


def require_capture_token(authorization: str | None = Header(default=None)) -> None:
    """Bearer-token gate for the ingress. 503 if unconfigured; 401 if bad/missing.

    Constant-time compare so a timing side-channel can't recover the token.
    """
    token = get_settings().capture.bearer_token
    if not token:
        raise HTTPException(
            status_code=503,
            detail="capture ingress not configured — run `mastisk capture-token`",
        )
    expected = f"Bearer {token}"
    if not authorization or not hmac.compare_digest(authorization, expected):
        raise HTTPException(status_code=401, detail="invalid or missing token")


class CaptureRequest(BaseModel):
    text: str = Field(min_length=1)
    source: Literal["watch", "phone", "pwa", "cli"] = "watch"
    # Reserved for Phase 2 relative-date resolution; accepted + ignored now.
    ts: str | None = None

    @field_validator("text")
    @classmethod
    def _non_blank(cls, v: str) -> str:
        if not v.strip():
            raise ValueError("text must be non-blank")
        return v


@router.post("", status_code=201)
async def capture(req: CaptureRequest, authorization: str | None = Header(default=None)) -> dict:
    require_capture_token(authorization)
    row = persist_note_capture(body=req.text, source=req.source)
    # Phase 1 always produces a note; the response shape is forward-compatible
    # with Phase 2's intent router (which will set type/needs_triage for real).
    return {
        "id": row["id"],
        "type": "note",
        "destination": row["path"],
        "needs_triage": False,
    }
```

> **Note on the auth wiring:** the `Header` param + explicit `require_capture_token(authorization)` call (rather than `Depends`) keeps the 422-on-blank-body validation ordering predictable and makes the handler trivially unit-testable. If the codebase prefers `Depends`, switch to `_: None = Depends(require_capture_token)` — both are fine; pick whichever matches existing route style after reading a couple of the other routers.

One-tap voice capture from the wrist: **Dictate Text → POST to your ingress**.

### 2. Expose ONLY /api/capture to the internet
The Apple Watch is **not** a Tailscale client, so the tailnet host won't resolve
from the wrist. Use Cloudflare Tunnel — and scope it to the capture surface only
(a bare tunnel to the whole app is a security hole; the bearer token is the
backstop, not the only control):

```bash
brew install cloudflared
cloudflared tunnel login
cloudflared tunnel create mastisk-capture
# Route a hostname to the local daemon, restricted to the capture path:
#   ingress:
#     - hostname: capture.<your-domain>
#       service: http://localhost:5555
#       path: ^/api/capture        # scope to the ingress
#     - service: http_status:404   # everything else → 404
cloudflared tunnel route dns mastisk-capture capture.<your-domain>
cloudflared tunnel run mastisk-capture
```
For stronger isolation, put a **Cloudflare Access** policy in front of
`capture.<your-domain>`. HTTPS is mandatory (the Watch enforces ATS) — Cloudflare
provides the TLS automatically.

Shortcuts app → new shortcut:
1. **Dictate Text** → (Language: your language; Stop Listening: On Tap)
2. **Get Contents of URL**

   - Method: `POST`
   - Headers: `Authorization` = `Bearer <token>`, `Content-Type` = `application/json`
   - Request Body: JSON → `text` = (Dictated Text), `source` = `watch`
3. (Optional) **Show Notification** with the `type` field from the response.

Name it "Capture". Enable **Show on Apple Watch**. Add it as a **watch-face
complication** for two-tap access (tap → confirm → speak).

### Limits (be aware)
- Dictation goes through Apple's servers (not local); needs Wi-Fi/cellular.
- ~30–60s practical dictation cap — designed for quick thoughts.
- `Get Contents of URL` POST from the Watch has been intermittently flaky across
  watchOS versions; test on your exact version.

## Risks & Follow-Ups

- **Tunnel scoping is a deployment concern, not enforced in code.** The bearer token is the app-level control we fully own; path-scoping/Access is documented but the operator must apply it. Flag prominently — a misconfigured tunnel exposes every route. Consider a Phase-2 hardening step: a middleware that 404s non-`/api/capture` paths when the request arrives via the tunnel hostname (detectable via `Host` header), so scoping is enforced in-app too.
- **`source` Literal widening.** `CaptureRequest.source` now allows `watch`/`phone`; the frontend `Note` type still lists only `pwa|cli|file`. The DB column is free TEXT so nothing breaks, but the PWA's TS union should gain `watch|phone` in Phase 2 to avoid a type cast.
- **`require_capture_token` called manually, not via `Depends`.** Chosen for predictable validation ordering + unit-testability; revisit if the codebase standard is `Depends`.
- **No rate limiting on the ingress.** A leaked token lets an attacker spam captures (noise, not data loss). Phase 2+ could add a simple token-bucket. Out of scope for Phase 1.
- **`ts` is accepted and ignored.** Wired into the request now so the Watch shortcut can send it from day one; Phase 2's relative-date resolver consumes it.
